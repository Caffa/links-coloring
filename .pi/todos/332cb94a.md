## Implementation Complete

Added tracking for precomputed files to skip redundant work on file switches.

### Changes Made

1. **Added `precomputedFiles` Set** (line 35):
   - Tracks which files have already had their link colors precomputed
   - Similar pattern to existing `openedFiles` Set

2. **Updated `precomputeFileLinkColors()`** (lines 192-207):
   - Early return if file already in `precomputedFiles`
   - Adds file path to set after successful precompute

3. **Updated `resetColorState()`** (line 470):
   - Clears `precomputedFiles` when settings/color state is reset
   - Ensures colors are recomputed after seed/palette changes

### Cache Invalidation

The `precomputedFiles` set is automatically cleared when:
- User changes seed (folder-based re-roll)
- Settings change (palette, hash mode, etc.)
- Theme changes trigger `resetColorState()`

### Performance Impact

Files are now only precomputed once per session (or after settings change), eliminating redundant:
- File content reading (though `cachedRead` is efficient)
- Link extraction
- Color computation (though `textColorMap` cache handles this)
